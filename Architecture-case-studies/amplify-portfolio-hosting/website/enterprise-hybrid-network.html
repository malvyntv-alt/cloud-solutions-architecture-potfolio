The business problem

A fictional financial institution is migrating its Dallas data center over 12–18 months. Production and Development need approved Shared Services, while Restricted Data remains reachable only from Production. The design supports migration coexistence without flattening those boundaries.

This personal, single-account lab demonstrates implementation choices and operational trade-offs. No real bank workload, customer data, regulatory certification, ROI or migration-time saving is claimed.

Engineering decisions

  • Explicit segmentation: TGW default association/propagation are disabled. Dedicated routing tables permit Production/Shared, Development/Shared and Production/Restricted. On-premises routes propagate only into Production and Shared.
  • Practical hybrid transport: strongSwan terminates IPsec and FRRouting supplies BGP. Site-to-Site VPN avoids purchasing a physical Direct Connect circuit. Production Direct Connect remains a design option using transit VIFs.
  • Private operations: SSM endpoints support management without SSH keys. Shared inbound/outbound Resolver endpoints bridge separate private namespaces.
  • Repeatability: native Terraform modules reuse the two-AZ VPC design. Files separate resource purposes, and mocked policy tests complement live verification.

A defect that changed the implementation

Reverse DNS forwarding initially timed out because Linux selected a VTI inside address for router-originated queries. The inbound Resolver allowed only the router's private host address. Binding dnsmasq upstream queries to 172.16.0.10 restored UDP/TCP resolution while preserving that narrow rule. The correction is in the bootstrap template; a fresh recreation still needs verification.

Resilience remains unfinished

Each tunnel was interrupted separately. Out of 75 samples per experiment, tunnel 1 recorded 22 failed TCP and 27 failed DNS samples; tunnel 2 recorded 15 and 44 respectively. These counts are not outage seconds or a proven RTO. The first baseline was unstable, and restoring both BGP sessions needed intervention.

The next work is bounded interruption/restoration commands, a stable baseline, verified peer recovery between tests and measured recovery intervals. Two tunnels sharing one EC2 router do not demonstrate router or site resilience.

Scope and cost

The lab ran in us-east-1 and was destroyed after evidence collection. The $5 session target was not a spending cap or a measured AWS invoice. Production would need redundant customer routers/sites and DNS servers, multi-account controls, protected remote state and operational ownership.
